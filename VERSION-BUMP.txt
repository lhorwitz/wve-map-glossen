Weevee version bump
===================

When the user says to bump the version, follow this file.

The repo is the source of truth and is NEVER renamed or restamped. A bump
does not touch the playable files here: no git mv, no repo rename, no
in-game title edit committed. Instead the bump builds a stamped copy
outside the repo, in Assets/Maps, plus a zip to hand out.

Current version: 11.0.5
Next version:    11.0.6   (set this as current after a successful bump)

The ledger lines above are the only thing in this repo a bump changes.

Names for version X.Y.Z
-----------------------
In-game title:    WvE Map X.Y.Z
Release folder:   wve_map_glossen_vX.Y.Z
Release lua:      wve_map_glossen_vX.Y.Z.lua
Release zip:      wve_map_glossen_vX.Y.Z.zip
Both land in:     ...\Sid Meier's Civilization V\Assets\Maps\
                  (the directory above this repo)

Repo lua stays "Weevee - v11.0.5.lua" forever. That filename is only a
handle for the build script; it is not the shipped name and does not
track the version.

Agent steps (in order)
----------------------
1. Confirm the new version number with the user if they did not give one.
   Default next is the "Next version" line above.
2. Commit any playable map changes that belong in this bump, message
   focused on why, then push to origin. Do this BEFORE building, so the
   release is cut from what is actually pushed.
3. Build the release from the repo root:

     .venv\Scripts\python.exe tools\bump.py X.Y.Z

   It copies every .lua out to Assets/Maps/wve_map_glossen_vX.Y.Z/,
   renames the map lua, stamps the version into it, syntax-checks the
   whole release against Lua 5.1, and writes the zip. If anything fails
   to parse it deletes the folder and ships nothing.

   Flags: --only-map excludes "oceanwve v2.0.lua" (a separate map script
   that shares the DEF modules); --force overwrites an existing release.
4. Update the ledger above: set Current version, set Next version (patch +1).
   Commit and push that change.
5. Tell the user the folder and zip are in Assets/Maps, and that the map
   appears in-game as "WvE Map X.Y.Z".

Notes
-----
- Players load the release FOLDER, not this repo. If the folder name does
  not match the version they agreed to play, it is the wrong copy.
- The zip unpacks to wve_map_glossen_vX.Y.Z/ — that folder is dropped
  straight into Assets/Maps.
- Do not change git config. Do not force-push. Do not --amend unless the
  commit protocol allows it.
- Local uncommitted edits are invisible to everyone else until step 2,
  but the build in step 3 reads the working tree, so an uncommitted edit
  WILL ship in the zip. Keep step 2 before step 3.

Tooling (in tools/, see tools/README.md)
----------------------------------------
  .venv\             Python venv with lupa; a real Lua 5.1 parser. Not
                     committed - create it once per clone with:
                       python -m venv .venv
                       .venv\Scripts\python.exe -m pip install -r tools\requirements.txt
  tools\luacheck.py  syntax-check every .lua in the repo
  tools\bump.py      build a stamped release

Lua 5.1 is what Civ V embeds, so luacheck catches the parse errors the
game would hit on load. It cannot catch runtime errors: Map, GameInfo,
PlotTypes and friends only exist inside the game.
